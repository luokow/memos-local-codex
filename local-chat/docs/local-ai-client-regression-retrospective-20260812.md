# Local AI 客户端连续回归复盘

## 结论

这次连续返工的根本原因不是某一个控件、某一个代理或某一行 XAML，而是开发工作流长期缺少五个连续门槛：**冻结已确认关系、限定本轮改动半径、验证外部运行时契约、验收真实安装产物、保留可恢复状态**。功能扩展直接进入大范围实现，静态检查和构建绿灯又被当成了用户可见结果，导致相邻设计、状态所有权和运行时必填字段在不同轮次反复丢失。

当前项目已经有 [winui-ui-baseline.md](winui-ui-baseline.md) 和 [winui-ui-baseline.json](winui-ui-baseline.json)。本复盘负责解释问题为何发生；[ui-change-ledger.json](ui-change-ledger.json) 负责把后续修改范围、保留关系、运行时契约和验收类型变成机器可检查的准入信息。

## 证据边界

- 问题序列来自本次对话中的十张汇总截图、当前源码、测试和部署入口。
- 截图里的“已部署”“真实窗口已验证”和测试数量属于历史陈述，本轮没有据此重新宣称当前安装版通过。
- 当前静态代码已经覆盖许多修复，但静态存在不等于真实 AppX、悬浮、滚动、关闭时序或 ComfyUI 运行结果已经复验。
- 本次优化不启动文本模型、视频模型，不重新生成视频，也不部署 AppX。

## 问题账本

| 阶段 | 用户可见问题 | 直接原因 | 更深层控制缺口 |
| --- | --- | --- | --- |
| 通用客户端首轮改造 | 原有退出提示消失，右上状态和模式切换被重排，聊天/视频页面切换跳动 | 在加入视频模式时同时重构共享外壳，没有逐项记录必须保留的邻接关系 | 改动前没有受影响关系账本；“新增能力”被误当成“允许重设计已有页面” |
| 设置扩展 | 文本/视频设置名称、位置和卡片结构不一致；视频参数写死或遗漏 | 两套设置分别增长，未共享信息架构；配置模型先按当前 Qwen/MiniMax 编码 | 缺少配对表面合约和数据驱动模型档案边界 |
| 视频预览 | 播放控制条遮住画面，预览框固定撑满，黑色方形底栏与全局圆角体系冲突 | 使用默认播放器控件和固定布局，未按实际视频比例与悬浮状态设计 | 静态 XAML/编译无法证明比例、悬浮、窗口缩放；真实窗口验收过晚 |

## 根本原因树

### 1. 需求边界没有转换成保留边界

用户授权的是“增加视频模式并把客户端通用化”，实现过程却没有先回答“哪些已有关系绝对不能动”。因此退出三选项、顶部状态字号、聊天输入层级等既有行为被当成可自由重排的实现细节。

根因：需求清单只描述新增内容，没有同时生成 `intended_change` 与 `preserve` 两栏。

### 2. 共享与隔离的边界反了

聊天和视频真正应该共享的是排版节奏、输入行为策略、设置卡结构和组件样式；真正必须隔离的是会话、错误、任务进度和模型生命周期状态。早期实现局部复制 UI、局部共享可见状态，造成视觉漂移和串台并存。

根因：没有配对表面关系表和状态所有权矩阵。

### 3. 验证层级与声明层级不匹配

编译、核心测试、静态 XAML 解析可以证明结构和纯逻辑，却不能证明播放条悬浮、比例缩放、退出首帧、滚动锚点、FolderPicker 弹出或安装版文件是否一致。多轮完成声明使用了较低层证据支持较高层结论。

根因：没有在实现前为每项主张指定 `static / functional / real-window / temporal / runtime / artifact-identity` 证据。

### 4. 外部运行时契约没有成为源码契约

H3 曾用真实工作流成功生成，但客户端模板后来仍漏掉 `SaveVideo.format`。说明“成功的运行时图”没有被当成权威输入，复制和节点映射也没有由必填字段测试保护。

根因：mock 能接收请求被误当成外部节点兼容；缺少“本地 schema 或已成功图 → required inputs → 回归断言”的链路。

### 5. 恢复能力依赖人工记忆

修改一直有 Git 工作区和历史对话可供比对，但没有每轮明确列出恢复对象、改动范围和回退步骤。用户只能通过截图逐项指出丢失内容，代理再从代码和对话中重建原设计。

根因：有版本痕迹不等于有可操作恢复点；缺少排除模型和构建产物的源代码/配置恢复清单。

## 新工作流

今后现有 WinUI 产品的修改必须按以下顺序执行：

1. **读取权威基准**：项目设计基准、机器合约、已安装产物和外部运行时工件。
2. **建立恢复点**：记录 Git diff 或受限源代码/配置归档；明确回滚文件，不备份模型、缓存、输出和凭据。
3. **填写变更账本**：每个表面分别写本轮允许变化和必须保留的邻接关系；配对页面写共享关系与状态所有者。
4. **冻结运行时契约**：从真实本地 schema、官方本地节点定义或已成功工作流提取必填输入；不靠网上片段或宽松 mock 猜测。
5. **小步实现**：一项行为一个 RED→GREEN，随后立即跑相邻保留检查；不顺带“美化”未授权区域。
6. **分层验证**：静态、功能、真实窗口、时序、运行时、安装产物身份分别给证据；没有对应证据就明确写未覆盖。
7. **安装版复验**：核对构建/AppX 身份，在真实窗口检查配对页面、悬浮、缩放、滚动、选择器和关闭分支。
8. **更新基准**：只有用户明确批准新的长期设计关系，才更新基准；不能为了让测试通过而放宽基准。

## 当前防线与剩余边界

已落地：

- 项目唯一设计基准与机器可读 XAML 合约；
- 聊天/视频输入、状态隔离、退出三分支、视频预览和模型档案的静态/核心回归；
- `SaveVideo` 的 `format`、`codec` 映射断言；
- 部署时的基线检查、核心测试、AppX 注册与 DLL 哈希对账；
- 本次新增的变更账本验证，防止保留关系、运行时契约或真实窗口证据再次被省略。

仍需按具体改动执行而不能由文档替代：

- 已注册 AppX 的聊天/视频切换、长历史锚点、展开编辑、悬浮/缩放、退出首帧和 FolderPicker 动态验收；
- 目标 ComfyUI 版本的真实节点 schema 检查与受控最小提交；
- 模型冷启动、失败、释放和“仅退出/退出并关闭服务”生命周期验收。

## 关于备份

过去并非完全没有恢复依据：当前 Git diff、历史设计文档、截图和部署产物都能帮助找回内容；但它们没有被组织成每轮可直接执行的恢复清单，所以恢复成本落到了用户逐项发现问题上。新流程要求每次先写 `recovery.strategy`、`location` 和 `rollback`，把“有痕迹”提升为“可回退”。
