# Local AI WinUI UI 基线

本文件是 Local AI 桌面客户端的唯一设计基准和视觉保留账本。后续功能修改必须先读取本文件；没有被当前需求明确授权的布局、层级、字体、圆角和交互关系不得顺手改动。产品专属数值由同目录的 `winui-ui-baseline.json` 提供，部署脚本会读取并验证可自动检查的部分。

基准状态：2026-08-12，经用户对聊天页、视频页、设置抽屉和退出页的多轮截图反馈确认。截图只代表稳定视觉帧；关闭时序、悬浮、滚动、比例变化等动态行为仍须真实窗口验收。

## 验收对象

- 显示名称：`Local AI`
- AUMID：`7D1F07DC-0090-4570-868B-B0D5D40CFB40_1z32rh13vfry6!App`
- 用户实际运行对象：注册后的 loose-layout AppX 中的 `QwenLocalChat.WinUI.exe`
- 源码构建不能代替桌面产物验收；构建 DLL 与 AppX DLL 的 SHA-256 必须一致。

## 视觉保留账本

| 表面 | 必须保留的视觉关系 | 本轮允许变化 | 验证 |
| --- | --- | --- | --- |
| 顶部品牌与状态 | 品牌区在左；聊天模型、记忆、日志三个紧凑状态芯片在右；保持原有状态字号、圆角和间距，不放大成操作卡 | 无 | XAML 合约 + 真实窗口 |
| 模式工具栏 | `聊天 / 视频 / 汉化` 使用同一个左对齐 `SelectorBar`；模式专属工具位于同一行剩余区域，不把模式切换做成居中悬浮大按钮。视频模式复用聊天的窗口控件：左侧会话列表、新建、删除；更多菜单可清空当前窗口。汉化页不提供多窗口会话 | 增加第三项「汉化」 | XAML 合约 + 真实窗口 |
| 聊天与视频主区 | 两个模式沿用同一纵向节奏：主要内容、输入卡、底部操作区；切换时外框和按钮层级不跳动 | 无 | 结构对比 + 真实窗口切换 |
| 汉化主区 | 主区是任务日志（左上标题「任务日志」），不是聊天记录；空闲时说明选目录后点开始即可自动跑完全程，不用点右上角启动。输入卡主按钮是唯一的「开始汉化」，底栏只保留设置 / 打开结果，运行中才出现取消。底栏状态行对标视频：步骤、已用时、剩余约、阶段计数；百分比只在条右侧。失败摘要用中文说明原因和下一步 | 去掉底栏重复开始按钮；主区标明任务日志；底栏接上视频同款时间进度；失败像视频一样说人话 | XAML 合约 + 真实窗口 |
| 输入卡 | 聊天和视频输入均使用 `RaisedBrush`、强边框、18 圆角和相同内边距语法；内部统一为“左侧标题 + 右侧精简元数据、输入框、可选辅助提示”；标题、摘要、正文和快捷提示分别共用同一字体资源；模型名只在顶部工具栏展示，输入卡不重复；主按钮位于正文行最右并垂直居中，不得被标题行元数据挤偏；两边都提供同位置的“展开编辑”。输入正文按内容和窗口高度在 3 至 8 行范围内自适应，超过当前上限后只在输入框内部纵向滚动；视频参数展开态最多保留 4 行输入，避免无限挤压预览。视频标题行右侧放紧凑生成模式下拉（对齐聊天侧上下文/输出上限元数据位），文生模式下不占额外媒体行；图生/参考图仅在需要时展开一行横向媒体条。默认折叠的轻量“生成参数”行：透明背景、单条上分隔线，折叠时只显示尺寸和时长数值；展开后在其下方显示独立圆角内容面，并用三列两行参数网格临时修改宽高、时长、步数和种子，不移动底部命令栏，在 960×740 常规窗口中仍须完整显示底部操作 | 模式与媒体控件压缩进标题行/按需条，保持与聊天输入卡同高节奏 | 纯布局策略测试 + XAML 直接对比 + 真实窗口 |
| 视频预览 | 外层圆角表面；窗口尺寸变化时按视频宽高比自适应；播放控件默认隐藏，仅悬浮或键盘聚焦显示。新建或清空后的窗口不自动带入输出目录里最新的成片，只恢复该窗口自己绑定的文件 | 预览按窗口绑定，不再全局抢最新文件 | 比例单测 + 会话预览单测 + 真实窗口 |
| 视频操作区 | 状态、进度条和百分比作为一组垂直居中、彼此贴近；百分比只出现在条右侧。右侧仍是 `设置 / 文件位置 / 生成视频` | 状态与进度收成一组，去掉重复百分比 | XAML 合约 + 真实窗口 |
| 设置抽屉 | 右侧 500 宽；文本/视频用同一个 `SelectorBar`；同类模型卡使用相同字段和位置；数字框固定宽度并顶部对齐；模型启动属于主页面操作，不藏在设置卡。每次打开设置或切换文本/视频分区时，内部滚动位置回到顶部。视频模型档案参数使用独立、默认展开的圆角区，可编辑显示名称、帧率、帧对齐和能力范围，不在普通编辑中改写工作流与节点映射 | 让视频档案参数可发现、可编辑 | XAML 合约 + 真实窗口滚动与保存重载 |
| 退出页 | 使用应用内圆角遮罩页，不切回曾导致原生崩溃的 `ContentDialog`；始终提供“仅退出 / 退出并关闭模型服务 / 取消”三个清晰选择 | 恢复三选择并让点 X 后立即显示 | 核心测试 + 真实窗口时序 |

颜色、柔光背景、边框层级、按钮主次和圆角不在本轮授权范围内。若未来确需改变，必须先在本表记录旧关系、变更理由和新的真实窗口证据，再更新自动基线；不能为了让测试转绿而直接替换基准。

## 交互基线

| 场景 | 必须保持的结果 | 证据 |
| --- | --- | --- |
| 正在生成 | 输入框保持启用、可编辑且不变灰；仅发送按钮禁用 | 核心测试 `busy-composer-keeps-editable-appearance` 加真实窗口状态检查 |
| 提交与回复完成 | 你的本轮问题对齐聊天视口前缘；回复完成后仍以该问题为锚点 | 两轮长回复真实窗口验收 |
| 模式状态隔离 | 聊天轮次、会话和错误提示只在聊天页展示；视频任务状态只在视频页展示，切页不串用同一个可见状态栏 | 模式切换回归 + 真实窗口 |
| 两种输入 | 聊天和视频都支持 Enter 提交、Shift+Enter 换行、上下键历史；长文本可打开同一风格的应用内展开编辑页，关闭后内容回写且不丢失 | 核心键盘策略 + UI 合约 + 真实窗口 |
| 本次视频参数 | 新任务从全局视频设置初始化；输入卡内修改只作用于当前提交，不写回全局设置。恢复默认值仅重填本次参数 | Core 合并测试 + 设置存储往返 + 真实窗口 |
| 展开编辑 | 使用应用根层内居中的圆角编辑面板，不使用依附右侧按钮的 Flyout；编辑器随面板完整显示，禁用横向滚动，只有正文区域允许纵向滚动；底部固定提供收起和对应提交动作 | UI 合约 + 真实窗口 |
| 视频错误 | 页脚状态行只显示一行摘要（显存不足等）；完整报错放在“查看详情”里可选择复制 | XAML 合约 + 摘要单测 + 真实失败填充验收 |
| 长历史滚动 | 聊天内容由 `ListView` 原生滚动；背景装饰不随文本重复绘制 | 真实窗口连续滚动验收 |
| Markdown 正文 | 标题、粗体、斜体、列表、引用、行内代码、代码块、HTTP(S) 链接和分隔线按语义显示，不暴露语法标记；一条消息只允许一个可选择文本所有者，鼠标选择必须能跨 Markdown 分块 | 解析器回归 + 真实窗口验收 |
| Markdown 安全 | HTML 仅作为文本显示；非 HTTP(S) 链接不可点击 | 解析器回归 |
| 整条复制 | 仅 Qwen 回复在标签旁提供“复制整条回复”按钮；SYSTEM 与用户消息不显示按钮；一次复制全部 Markdown 分块的可读纯文本，同时保留鼠标自由选择 | 角色策略回归 + 纯文本合并回归 + 真实剪贴板验收 |
| 清空会话 | 只清理当前上下文，不删除 MemOS 和日志文件 | 功能测试与真实窗口检查 |
| 开关悬浮 | 使用 WinUI 平台默认 `ToggleSwitch` 悬浮视觉，不在 `App.xaml` 全局重定向 `*PointerOver` 主题资源（设置「思考模式」开关已确认可触发 `Microsoft.UI.Xaml` 原生闪退；A/B 先去掉全局覆盖） | XAML 禁止覆盖门禁 + 真实窗口拨动验收 |
| 模型驻留 | 默认开启文本/视频显存互斥；关闭后切换功能不自动释放另一模型，但仍不允许在已有生成任务时启动第二个任务 | 设置往返测试 + 四个启动入口回归 |
| 文件位置 | 有成片时打开资源管理器并选中该文件；生成中尚无成片时打开输出目录；不调用默认播放器 | 参数构造测试 + 真实资源管理器验收 |
| 默认启动 | 默认启动当前所选文本模型；设置可改为当前所选视频模型或不自动启动。聊天/视频主页面各自提供当前模型的“启动”按钮，生命周期状态不得写死 | 设置往返测试 + 真实冷启动/失败/释放验收 |
| 退出选择 | 点 X 后先显示选择页，不把模型健康检查放在首帧前；“仅退出”不停止服务，“退出并关闭模型服务”执行安全停止/卸载，“取消”返回应用 | 协调器测试 + 真实窗口时序 |

滚动、恢复、首次可见帧属于时间过程，静态截图不能单独证明通过。凡修改聊天列表、消息模板、滚动、窗口生命周期、模式切换、设置抽屉或视频预览，必须重新执行真实窗口动态验收。

运行时文案不使用中点 `·` 充当分隔符；输入卡元数据通过留白与布局分组。聊天和视频页右侧模型摘要使用相同对齐、字号和垂直位置。文本输入卡只展示上下文和输出上限；视频输入卡只展示分辨率和时长；模型名称统一留在顶部工具栏，避免重复。

## 变更准入

1. 修改前列出本文件中受影响的关系，区分静态、功能、时序和发布产物证据。
2. 新行为先做 RED→GREEN；相邻视觉关系同步加入保留断言。
3. 静态 XAML 解析不能证明悬浮、关闭延迟、滚动和缩放，必须检查已部署 AppX 的真实窗口。
4. 若设计基准与通用 UI 建议冲突，本项目已确认的基准优先；通用建议只补足本文件未规定部分。
5. 更新基准本身属于设计审批动作，必须能指向用户明确反馈或批准，不能由实现者自行放宽。

不要在应用资源字典中全局覆盖 `ToggleSwitch*PointerOver` 主题键。历史实现曾用 `StaticResource` 重绑悬浮轨道/滑块，随后在设置「思考模式」开关上稳定复现 `Microsoft.UI.Xaml.dll` `c0000005`，转储栈经过输入路径与 `OverrideXamlResourcePropertyBag`。当前合约是平台默认悬浮视觉；若将来恢复自定义悬浮，必须先用 procdump 证明不再触发同一原生崩溃，再单独更新本基线。

## 发布门禁

运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy-winui.ps1
```

脚本必须依次通过：

1. WinUI UI 基线解析与 XAML 合约检查；
2. 核心行为测试；
3. loose-layout AppX 构建与注册；
4. 构建 DLL 与 AppX DLL 哈希一致性检查。

任何一项失败都不能宣称桌面版已更新。
