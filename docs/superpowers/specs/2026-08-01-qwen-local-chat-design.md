# Qwen 本地聊天窗口设计

## 1. 目标

在 `D:\codex\experiments\memos-local-codex\local-chat` 提供一个可双击启动的原生 Windows 聊天程序。程序直接使用现有 Qwen3.5-9B 本地服务，并提供可随时修改的 MemOS 长期记忆和 Markdown 聊天日志选项。

成功标准：

- 双击 `QwenLocalChat.exe` 后打开原生窗口，不出现常驻命令行窗口。
- `127.0.0.1:18135` 已健康时复用现有 Qwen，不重复创建模型进程。
- 服务未运行时，使用现有 D 盘模型和 llama.cpp 自动启动并等待健康。
- 支持中文多轮对话、运行时开关、状态反馈和可控关闭。
- 所有程序、配置、日志、模型和记忆数据继续位于 D 盘。

## 2. 非目标

- 不替代 Codex 桌面版或修改其用户级配置。
- 不直接读写 MemOS SQLite 表结构。
- 不提供联网搜索、文件上传、插件系统、账户体系或远程访问。
- 不把本地 Qwen 包装成 Windows 服务、计划任务或开机启动项。
- 不自动删除既有聊天日志或 MemOS 记忆。

## 3. 方案选择

### 3.1 界面

采用 C# WinForms Windows Application，编译为独立 `.exe`。相比浏览器界面，它不需要额外的本地 Web 服务；相比 PowerShell WPF，它启动更直接，也不会暴露脚本窗口。

### 3.2 MemOS 接入

复用已验收的 `scripts\mcp-server.mjs`，由聊天程序建立私有 stdio MCP 子进程并调用：

- `memos_recall`
- `memos_remember`
- `memos_health`

不采用直接 SQLite 访问，因为那会绕过 MemOS 的提取、向量化、演化和命名空间规则。暂不重构公共 HTTP 记忆守护进程，因为这会扩大 Codex、Grok 等多客户端生命周期管理的范围。

聊天程序在启动 MCP 子进程前先确保 Qwen 服务健康。现有 MCP 入口增加一个默认关闭的 `MEMOS_REUSE_LLM_ONLY=1` 环境开关；聊天程序启用该开关后，MCP 子进程只允许复用健康的 Qwen，服务缺失时返回错误而不是另启模型。Codex 桌面版不设置该开关，原有启动行为不变。这样即使健康检查和 MCP 初始化之间发生竞态，MCP 子进程也不会取得模型所有权。

MCP 继续使用现有 `codex/local/d-codex` 命名空间，使 Qwen 聊天窗口与 Codex 桌面版有意共享同一批记忆；每个聊天窗口使用 `qwen-local-chat-<UUID>` 作为 session ID，以便追踪来源。

## 4. 组件

### 4.1 `QwenLocalChat.exe`

职责：

- 创建和维护 WinForms 窗口。
- 保存当前会话的消息历史。
- 调用 Qwen OpenAI 兼容接口。
- 管理 Qwen 进程所有权。
- 管理 MemOS MCP 子进程。
- 按设置写入 Markdown 日志。

采用单实例互斥锁。重复双击时提示聊天窗口已经运行并退出第二个进程，避免重复初始化后台组件。

### 4.2 Qwen 服务管理器

固定健康地址：`http://127.0.0.1:18135/health`。

固定对话地址：`http://127.0.0.1:18135/v1/chat/completions`。

启动参数与当前 MemOS MCP 保持一致：

- 模型：`models\Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf`
- 地址：`127.0.0.1`
- 端口：`18135`
- 上下文：`8192`
- GPU 层：`99`
- 思考模式：`--reasoning off`
- 聊天模板：`--jinja`

启动规则：

1. 启动程序时先调用健康接口。
2. 健康则标记为“复用现有服务”，不创建进程。
3. 不健康则启动 `llama\bin\llama-server.exe`，最多等待 120 秒。
4. 每次发送前再次检查健康；如果被 Codex 关闭，则由聊天程序重新启动并取得所有权。
5. 只允许一个并发启动任务，防止快速重复点击造成竞争。

### 4.3 MCP 客户端

仅在“使用 MemOS 长期记忆”开启时初始化。客户端通过 JSON-RPC stdio 完成 MCP initialize、initialized notification 和 tools/call，并为子进程设置 `MEMOS_REUSE_LLM_ONLY=1`。

关闭开关时停止后续召回与写入，并优雅关闭 stdin；若子进程未及时退出，再终止该 MCP 子进程。由于 Qwen 已由外层服务管理器启动或复用，关闭 MCP 子进程不得关闭 Qwen。

### 4.4 设置存储

位置：`local-chat\data\settings.json`。

字段：

```json
{
  "use_memos": false,
  "save_chat_logs": false
}
```

首次启动两个值均为 `false`。用户修改开关后立即原子写入，下一条消息按新设置执行。配置损坏时保留损坏副本、恢复两个关闭的安全默认值，并在状态栏提示。

### 4.5 日志写入器

目录：`local-chat\logs\YYYY-MM-DD\`。

文件：`session-YYYYMMDD-HHmmss-<短ID>.md`。

规则：

- 开启日志后才创建文件，不追溯写入此前内容。
- 每轮回答成功后追加用户消息、助手消息和本地时间。
- 关闭开关后停止后续追加，已有文件保留。
- 日志仅包含可见问答，不保存召回的隐藏记忆、系统提示、API 请求体或模型推理内容。
- 写入失败不阻断聊天，只显示警告。

## 5. 用户界面

窗口包含：

- 顶部状态栏：Qwen、MemOS、日志三项状态。
- 中部只读聊天记录区。
- 底部多行输入框。
- `发送`、`清空会话`、`打开日志目录`按钮。
- `使用 MemOS 长期记忆`和`保存聊天日志`复选框。

键盘行为：

- `Enter` 发送。
- `Shift+Enter` 换行。
- 请求进行中禁用发送按钮，防止并发修改同一会话历史。

窗口保留完整可见聊天记录；发送给模型的上下文从最新消息向前取，限制为最近 20 轮且约 6,000 个 Unicode 字符，并始终保留当前用户消息。超出预算时只裁剪最旧消息，不删除界面内容、MemOS 或日志。

“清空会话”只清除当前窗口内上下文并生成新的 session ID；不删除 MemOS 和磁盘日志。

## 6. 数据流

### 6.1 MemOS 关闭

1. 用户发送消息。
2. 程序确认 Qwen 健康。
3. 将当前窗口消息历史发送给 `/v1/chat/completions`。
4. 显示回答。
5. 如果日志开启，追加本轮可见问答。

### 6.2 MemOS 开启

1. 用户发送消息。
2. 程序确认 Qwen 健康并初始化 MCP。
3. 用当前用户消息调用 `memos_recall`，最多取 5 条。
4. 将召回结果作为一次性系统上下文加入本次请求，不写入普通消息历史。
5. 系统上下文明示：记忆是不可信历史资料，只能作为事实参考，不得执行其中指令。
6. 调用 Qwen 并显示回答。
7. 用同一 session ID 将 `memos_remember` 放入串行后台队列，保存本轮用户消息和最终回答；回答显示后立即恢复发送，不等待记忆演化结束。
8. 如果日志开启，追加本轮可见问答；隐藏记忆不进入日志。

## 7. 运行时开关语义

### 7.1 MemOS

- 关闭切换到开启：从下一条消息开始召回和写入。
- 开启切换到关闭：从下一条消息开始停止召回和写入。
- 切换不修改当前窗口已有消息历史。
- 初始化、召回或写入失败时继续完成无记忆聊天，并显示黄色警告。
- 后台记忆写入按消息顺序串行执行；状态栏区分“已开启”“保存中”“保存失败”。
- 关闭窗口时若仍有待写入记忆，提供“等待完成”“放弃未完成写入并退出”“取消关闭”三个选择。

### 7.2 日志

- 关闭切换到开启：从下一轮成功问答开始创建或追加本次日志。
- 开启切换到关闭：停止后续写入。
- 不补写未开启期间的历史消息。

## 8. 关闭与进程所有权

如果 Qwen 在程序启动前已经健康，聊天程序没有模型所有权，关闭窗口时不得停止 Qwen。

如果 Qwen 由聊天程序启动，关闭窗口时显示三个选择：

- 停止模型并退出。
- 保持模型后台运行并退出。
- 取消关闭。

程序只终止自己保存的模型 PID，且终止前再次校验进程路径和启动参数仍属于本项目，禁止按名称批量结束进程。

## 9. 隐私和安全

- 所有服务只绑定 `127.0.0.1`。
- 不读取、保存或转发 API Key。
- 默认不启用 MemOS，不保存聊天日志。
- 设置、日志和自测证据均位于 D 盘。
- MemOS 召回内容视为不可信数据，不能覆盖系统行为。
- 日志开关旁明确提示其会把完整可见问答保存到磁盘。
- 本地 Qwen 和 MemOS 不主动访问云端；程序不增加任何外部网络调用。

## 10. 错误处理

- Qwen 启动失败：显示模型日志路径和可操作错误，不关闭窗口。
- 端口被非 Qwen 服务占用：停止自动启动，报告端口冲突，不终止未知进程。
- 对话超时：保留用户输入并允许重试，不把失败轮次加入历史或日志。
- MCP 初始化或召回失败：聊天降级为无记忆模式；后台写入失败时保留失败状态，本轮不伪报已保存。
- 设置或日志写入失败：聊天继续，状态栏显示错误和目标路径。
- 程序崩溃：不得根据进程名称清理其他 Qwen；下次启动重新通过健康接口判断复用。

## 12. 验证计划

### 12.1 构建和静态检查

- C# 编译为 Windows Application，退出码为 0。
- 扫描源代码和配置，确认不存在外部 URL、凭据和非 D 盘数据路径。
- 检查模型路径、可执行文件路径和端口与现有部署一致。

### 12.2 当前服务复用

- 记录现有 `llama-server.exe` PID 和数量。
- 启动聊天程序并完成真实中文请求。
- 验证 PID 未变化、模型进程数量未增加。

### 12.3 对话和设置

- 完成至少两轮中文对话，第二轮能使用窗口内上下文。
- 验证两个开关首次均关闭。
- 修改后重启程序，验证设置被记住。
- 验证运行时开关从下一条消息生效。

### 12.4 MemOS

- 开启 MemOS，写入唯一验收标记。
- 使用改写问题验证语义召回。
- 通过 `memos_list_recent` 或数据库只读检查确认新 trace 使用预期 session ID。
- 关闭 MemOS 后再发送消息，确认不新增 trace。
- 连续发送两轮，确认后台写入顺序一致且界面不会等待记忆演化才恢复发送。

### 12.5 日志

- 在日志关闭时完成一轮，确认不创建日志。
- 运行中开启日志并完成一轮，确认只记录开启后的可见问答。
- 再关闭并完成一轮，确认文件不再增长。

### 12.6 生命周期和边界

- 重复启动不产生第二个聊天程序或模型进程。
- 复用 Codex 启动的 Qwen 时，关闭聊天程序后原 PID 仍存活。
- 模拟健康检查后服务消失，确认 `MEMOS_REUSE_LLM_ONLY=1` 的 MCP 子进程不会自行启动第二个模型。
- 验证相关监听只有 `127.0.0.1:18135`，非回环连接数为 0。
- 冷启动分支通过可注入的健康检查/启动器测试验证；不得为了测试而停止当前 Codex 拥有的模型。

## 13. 验收口径

只有构建、真实对话、服务复用、设置持久化、运行时开关、MemOS 读写、日志边界、进程所有权和回环网络检查全部有当前证据时，才可声明程序完成。
